description: How to place buttons, links and menus so every screen has one clear next step. Hierarchy by emphasis, neutral for actions, coral only when something will be destroyed.

## One clear next step

Each view has **at most one** `primary` button: the thing most people came to do. Everything else steps down.

| Emphasis | Variant | Use for |
|---|---|---|
| Highest | `primary` | The main action: "Create agent", "Save changes" |
| Medium | `secondary` | Alternatives next to it: "Cancel", "Preview" |
| Low | `ghost` | Toolbars, rows, cards, icon buttons |
| Inline | `link` | Actions inside a sentence, or that navigate |
| Danger | `destructive`, `ghost-destructive`, `link-destructive` | Delete, remove, disconnect |

```tsx
<div className="flex justify-end gap-2">
  <Button variant="secondary">Cancel</Button>
  <Button>Save changes</Button>
</div>
```

Put the primary action last (on the right) in dialogs, forms and footers; secondary actions to its left, 8px apart (`gap-2`).

## Labels

<Guidelines>
  <Guideline>Verb + noun, in sentence case: "Connect provider", "Rename agent". Not "Submit", "OK" or "Click here".</Guideline>
  <Guideline>Say what will happen: "Create agent" tells people the result; "Continue" doesn't.</Guideline>
  <Guideline dont>Don't use all caps, and don't end with a full stop.</Guideline>
</Guidelines>

## Sizes

Controls are `sm` 32px, `md` 36px (default) and `lg` 40px. `lg` is the largest, also on mobile, where touch targets are at least 40px. Use `xs` (28px) only in dense chrome like toolbars. Inputs and selects share these sizes, so a button sits level with the field next to it.

## Icon buttons

```tsx
<Tooltip>
  <TooltipTrigger asChild>
    <Button variant="ghost" square aria-label="Copy link"><Link2 /></Button>
  </TooltipTrigger>
  <TooltipContent>Copy link</TooltipContent>
</Tooltip>
```

An icon-only button always has an `aria-label` and a tooltip with the same words. Icons go straight inside Button; it sizes them.

## Several actions

- **Up to three** related actions: show them as buttons.
- **More than three**, or actions on each row or card: a `ghost` `square` ⋯ button that opens a [Dropdown menu](/library/components/dropdown-menu) with `align="end"`.
- In a menu, write rows as verb + noun, most used first, and put destructive rows last after a separator.

## Destructive actions

Coral means something will be destroyed or removed. It's the only place coral appears on an action.

| Situation | Do |
|---|---|
| Delete one thing, easy to undo | `ghost-destructive` or a destructive menu row, then an undo toast |
| Delete something permanent or large | Confirm in a dialog that names it: "Delete *Research agent*?" with a `destructive` button "Delete agent" |
| Remove inline, e.g. disconnect | `link-destructive` |

<Guidelines>
  <Guideline>Name the thing and the consequence in the confirmation: "Its chats and memory are deleted for everyone."</Guideline>
  <Guideline dont>Don't make the destructive button the default focus in a dialog; focus Cancel.</Guideline>
  <Guideline dont>Don't color a non-destructive action coral to get attention.</Guideline>
</Guidelines>

## Disabled and loading

- **Loading:** `<Button loading>` keeps the width, shows a spinner and blocks clicks. Use it while an action runs instead of disabling.
- **Disabled:** only when the action truly can't happen yet, and say why: helper text, or a tooltip on a wrapper (a disabled button can't show one). Often it's better to keep the button enabled and explain what's missing when it's pressed.
